# Re Relation 個別サポート会員サイト

既存Re Relation会員サイトの配色・余白・カード表現をデザイン基準として、新しく設計した個別サポート用会員サイトです。

既存サイトの複製ではなく、以下の機能に絞っています。

- 購入者専用ログイン
- 個人別ホームと受講進捗
- 動画講義
- ワーク回答と保存
- 運営者用の進捗・困りごと確認画面

## ファイル

- `index.html`: ログイン
- `dashboard.html`: 購入者専用ホーム
- `lectures.html`: 動画講義・ワーク
- `answers.html`: 保存した自分の回答を振り返る画面
- `admin.html`: 運営管理画面
- `styles.css`: 共通デザイン
- `app.js`: アカウント別コンテンツ・保存・画面動作
- `ayano-content.js`: あやのさん用の30回・300問の質問テンプレート
- `account-tests.cjs`: ID別保存・振り返り・既存回答引き継ぎの検査
- `brand-hero.png`: ログイン背景

## ローカル確認

```bash
python3 -m http.server 3010
```

`http://localhost:3010/` を開きます。

既存の001・002はブラウザ内保存の簡易版です。DB同期やサーバー側認証は未実装です。
ID・パスワード・質問テンプレートは公開ソースに含まれるため、機密性のある本番運用には使えません。
受講者の回答はGitHubへ送信されず、ID別キーでその端末・ブラウザのlocalStorageに保存されます。
別端末との共有はなく、ブラウザのデータ削除で失われます。管理画面も同じブラウザの回答だけを表示します。
この分離は通常の画面操作での混在を防ぐもので、第三者のアクセスを防ぐ本式の認証ではありません。

### ID 003：過去回答の振り返りと新しい回答の保存

共通ログイン画面から、これまでと同じ003の専用パスワードで `archive.html` を開きます。
32回分のワーク・過去回答273件・補足34タブを、2026-11-11に元シートから再取得して照合しました。
第1〜29回のワークと「学び・気づき」は原文を表示します。
第30〜32回はワークと「学び・気づき」に入力欄・保存ボタンがあり、保存後は別端末からも同じアカウントで確認・編集できます。
第31・32回に元からあった一部の回答は初期値と原文確認欄の両方に残します。
動画は以前送付したリンクの利用と必要時の再送を案内します。

- 元シートの取り込みは今回時点のスナップショットです。サイトで新しく保存した回答は専用DBへ保存され、シートへは自動で書き戻しません。
- `archives/003.json` は元記録のAES-256-GCM暗号文。PBKDF2-SHA256（600,000回）でブラウザ内復号します。元データとパスワードは公開リポジトリの外に保管します。
- 新しい回答はブラウザで別のAES-GCM鍵を導出して暗号化し、認証された保存API経由で専用Cloudflare D1へ保存します。サーバーには回答の平文やパスワードを保存しません。
- 保存APIの認証は、ブラウザで導出する専用の高エントロピー鍵で行います。認証鍵と回答暗号化鍵はHMACで用途を分離し、サーバーには認証鍵のSHA-256だけをWorker secretとして配置します。パスワード自体はAPIへ送りません。
- セッションはランダムな256ビットトークンで8時間有効。DBにはトークンのハッシュを保存し、ログアウトで失効します。会員IDは認証されたセッションから決定します。保存・取得は003と第30〜32回に限定します。
- 通信失敗時には暗号化した下書きをlocalStorageへ残し、成功した保存とは区別して表示します。未保存入力がある場合は離脱前に通知します。保存前のログアウトでも暗号化下書きを残します。
- 別端末の更新とはバージョンを照合し、競合時は両方の内容を確認して選べます。サーバーには保存履歴も残します。同じリクエストの再送では重複版を作りません。
- DBは `lily-middle-works`、APIは `lily-middle-work-api`。既存の他用途のDBは使用しません。管理画面でWorkers Freeを確認済みです。有料プラン・R2・Supabaseは有効化していません。無料枠を超えた場合は操作がエラーになり、自動課金はありません。詳細: https://developers.cloudflare.com/d1/reference/faq/
- 従来の管理画面は001/002用のままです。運営者が003の記録を見る場合も専用IDとパスワードを使います。
- 元の質問文が空欄の5か所はその旨を表示します。視聴完了や回答の補作は行いません。
- 旧暗号文と旧パスワードを保有する相手から、既に取得済みの過去記録を遠隔削除することはできません。短いパスワードへ変更しないでください。

新しい回を追加する際は、`work-sync-config.js` の `lastRound` と `backend/wrangler.jsonc` の `LAST_ROUND` も同じ番号へ更新します。
`salt` / `keyId` は保存回答の復号に必要なので、移行処理なしで変更しないでください。
APIの認証ハッシュは公開コードへ含めず、Wranglerの通常のsecret設定で管理します。
ローカル試験では `scripts/preview-server.cjs http://127.0.0.1:8787` を使うと、公開ファイルだけを配信しローカルAPIへ接続できます。試験用DBと本番DBを分けてください。

`scripts/pack-archive.cjs` はリポジトリ外の移行データから暗号化する運営者用ツールです。
標準出力には認証情報も含むため、そのままファイル化してコミットしないでください。
公開するのは `envelope` のみです。元データと認証情報はリポジトリ外で安全に管理します。
更新時は再取得した原文を確認して、現在の認証情報を指定して暗号化し直します。

暗号化方式の参考: https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey

あやのさんの取り込みは質問・ねらい・注意書きのみです。記入例と過去の本人回答は含みません。
第1回〜第27回のワーク・登録動画を「過去に取り組み済み」と表示します。第28回〜第30回は初期状態では未完了です。
ミサキさんの旧保存キーは、001でログインした際に専用キーへコピーし、原本も残します。

## コンテンツ追加ルール

- 初期状態は講義0件
- 1回分は「動画講義＋ワーク」のセット
- 最初のセットを第1回、次のセットを第2回として追加
- ミサキさんは `app.js` の `misakiSessions`、あやのさんは `ayano-content.js` の `ayanoSessions` に登録
- 動画URL未登録の場合はワークだけ表示。後から同じ回へ動画を追加できる
