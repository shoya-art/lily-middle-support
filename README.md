# Re Relation 個別サポート会員サイト

既存Re Relation会員サイトの配色・余白・カード表現をデザイン基準として、新しく設計した個別サポート用会員サイトです。

既存サイトの複製ではなく、以下の機能に絞っています。

- 購入者専用ログイン
- 個人別ホームと受講進捗
- 動画講義
- ワーク回答と保存
- 運営者用の進捗・困りごと確認画面

## ファイル

- `index.html`: ログイン
- `dashboard.html`: 購入者専用ホーム
- `lectures.html`: 動画講義・ワーク
- `answers.html`: 保存した自分の回答を振り返る画面
- `admin.html`: 運営管理画面
- `styles.css`: 共通デザイン
- `app.js`: アカウント別コンテンツ・保存・画面動作
- `ayano-content.js`: あやのさん用の30回・300問の質問テンプレート
- `account-tests.cjs`: ID別保存・振り返り・既存回答引き継ぎの検査
- `brand-hero.png`: ログイン背景

## ローカル確認

```bash
python3 -m http.server 3010
```

`http://localhost:3010/` を開きます。

現在はブラウザ内保存の簡易版です。DB同期やサーバー側認証は未実装です。
ID・パスワード・質問テンプレートは公開ソースに含まれるため、機密性のある本番運用には使えません。
受講者の回答はGitHubへ送信されず、ID別キーでその端末・ブラウザのlocalStorageに保存されます。
別端末との共有はなく、ブラウザのデータ削除で失われます。管理画面も同じブラウザの回答だけを表示します。
この分離は通常の画面操作での混在を防ぐもので、第三者のアクセスを防ぐ本式の認証ではありません。

あやのさんの取り込みは質問・ねらい・注意書きのみです。記入例と過去の本人回答は含みません。
第1回〜第27回のワーク・登録動画を「過去に取り組み済み」と表示します。第28回〜第30回は初期状態では未完了です。
ミサキさんの旧保存キーは、001でログインした際に専用キーへコピーし、原本も残します。

## コンテンツ追加ルール

- 初期状態は講義0件
- 1回分は「動画講義＋ワーク」のセット
- 最初のセットを第1回、次のセットを第2回として追加
- ミサキさんは `app.js` の `misakiSessions`、あやのさんは `ayano-content.js` の `ayanoSessions` に登録
- 動画URL未登録の場合はワークだけ表示。後から同じ回へ動画を追加できる

## 検査

```bash
node --check app.js
node --check ayano-content.js
node account-tests.cjs
```
